# ВСТУП

## Актуальність теми

Вторинний обіг квитків на культурні, спортивні та розважальні заходи здійснюється через неспеціалізовані канали (соціальні мережі, месенджери, дошки оголошень) та через спеціалізовані платформи перепродажу. Неспеціалізовані канали не забезпечують перевірки автентичності квитка, гарантії розрахунків та контролю повторного продажу одного квитка кільком покупцям. Спеціалізовані платформи вирішують ці задачі частково: гарантія автентичності залежить від інтеграції з квитковим оператором організатора, а механізми протидії автоматизованому трафіку не завжди витримують пікові навантаження. Під час передпродажу туру Eras Tour у 2022 році платформа Ticketmaster отримала 3,5 млрд запитів, що вчетверо перевищило попередній пік, при цьому значну частку трафіку становили боти.

З інженерної точки зору задача вторинного обігу квитків поєднує кілька класів проблем: конкурентний доступ до унікального ресурсу (race condition при одночасній спробі придбати один квиток), протидію автоматизованим загрозам класів Scalping та Denial of Inventory за класифікацією OWASP Automated Threats to Web Applications, забезпечення автентичності цифрового квитка без доступу до систем організатора, фінансову цілісність угоди та незмінність журналу подій. Вирішення цих проблем потребує поєднання засобів керування ідентичністю (OAuth 2.0 / OpenID Connect), розподілених механізмів блокування й обмеження частоти запитів, криптографічних примітивів та гарантованої доставки подій, що визначає актуальність теми кваліфікаційної роботи.

## Об'єкт дослідження

Процес вторинного обігу електронних квитків у веб-середовищі в умовах конкурентного доступу та автоматизованого трафіку.

## Предмет дослідження

Методи та засоби забезпечення безпеки й транзакційної цілісності процесу перепродажу квитків: керування ідентичністю на основі OAuth 2.0 / OpenID Connect (Keycloak), обмеження частоти запитів за алгоритмом Token Bucket, розподілене та оптимістичне блокування (Redis, PostgreSQL), криптографічний підпис квитків за алгоритмом ECDSA, патерн Transactional Outbox з асинхронною взаємодією через RabbitMQ, реалізовані на платформі Java 21 / Spring Boot 3.

## Мета роботи

Розробка захищеної веб-платформи для перепродажу квитків на основі модульного моноліту з подієвою взаємодією модулів для виключення подвійного продажу квитка, протидії автоматизованому скуповуванню та забезпечення перевірюваної автентичності квитка в процесі вторинного обігу шляхом застосування методів розподіленого блокування, обмеження частоти запитів та криптографічного підпису квитків.

## Завдання проєкту

1. Проаналізувати предметну область вторинного обігу квитків та існуючі програмні аналоги, визначити їхні архітектурні обмеження та сформувати вимоги до системи.
2. Обґрунтувати вибір технологічного стеку та архітектурного стилю системи.
3. Спроєктувати архітектуру системи з використанням нотацій UML та C4 Model, модель даних і контракти API (OpenAPI).
4. Розробити алгоритми критичних вузлів системи: резервування квитка з розподіленим блокуванням, обмеження частоти запитів, криптографічного підпису та верифікації квитка, переходів станів замовлення.
5. Спроєктувати інтерфейс користувача та схему розгортання системи в контейнерному середовищі (Docker) з конвеєром CI/CD (GitHub Actions).
6. Провести інструментальний аудит якості та безпеки коду: модульне, інтеграційне та навантажувальне тестування (JUnit 5, Testcontainers, k6), статичний і динамічний аналіз безпеки (SonarQube, OWASP Dependency-Check, Trivy, OWASP ZAP).
7. Апробувати результати роботи у формі тез доповіді на науково-практичній конференції.
